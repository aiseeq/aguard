# cl

Короткий запуск Claude Code: `cl [аргументы claude]` = `claude --dangerously-skip-permissions --allowedTools=Grep,Glob
--add-dir=~/.cache/worktrees --add-dir=~/.cache/claude-tmp -n <имя> [аргументы]`.

`--allowedTools=Grep,Glob` возвращает в Bash настоящие `grep` и `find` вместо встроенных ugrep и bfs (и инструменты Grep и Glob),
остальной набор инструментов не меняется (tools-reference, «Glob tool behavior»; выключателя подмены нет, #69736). Его же
получает `cl -p`, подкоманды — нет. Флаг — обход: ночью его проверяет обход Сна `harness`.

`--add-dir` на `~/.cache/worktrees` (worktree от `graft worktree add`) и `~/.cache/claude-tmp` (`CLAUDE_CODE_TMPDIR`,
scratchpad): без него Claude Code 2.1.310 возвращает cwd Bash в корень сессии после каждого `cd` туда. Несуществующая
папка не передаётся. Его получают первый запуск, перезапуск и `cl -p`. После `cd` в такую папку Primary working
directory сессии меняется так же, как при `cd` в подкаталог корня; каталог проекта (транскрипт, автопамять, скрипты
Workflow) остаётся по папке запуска, `--resume` из неё находит беседу (пробы Сна 25.10).

Имя сессии — по папке запуска: строка таблицы `~/.config/cl/names.tsv` («папка<TAB>имя», `~` раскрывается),
иначе `<папка>-master` для `~/git/<папка>` и `~/work/<папка>`, иначе без имени. Имя занято живой сессией
(реестр `~/.claude/sessions/*.json`) — `-2`, `-3`… Свой `-n`/`--name`, `-p` и подкоманды (`cl mcp list`) — как у claude.

## Перезапуск на новую версию

Интерактивную сессию cl держит дочерним процессом. Раз в `check_seconds` он спрашивает aguard, можно ли перезапустить
её на установленную версию Claude Code (`~/.local/bin/claude` → `~/.local/share/claude/versions/<версия>`), и пишет
смену решения в журнал. Можно — только если всё сразу (`internal/restart/decide.go`; любое непрочитанное — нельзя):

- версия процесса (`/proc/<pid>/exe`) старее установленной;
- Claude Code считает сессию простаивающей (`status: idle` в реестре), а chooks — закончившей ход
  (`$XDG_RUNTIME_DIR/chooks/sessions/<сессия>`: `done` или `idle`; `waiting` — вопрос человеку); `paused` — только без фоновых задач
  на последнем Stop (нет файла `<сессия>.tasks`) и когда все таймеры восстановимы ролью;
- транскрипт, состояние и статус не менялись `restart.idle` конфига aguard, ввода в терминал столько же не было (atime pts);
- у процесса нет потомков (фоновые команды Bash, их дети, хуки);
- в транскрипте с начала жизни процесса нет инструмента без результата, фоновой команды, монитора или суб-агента
  без уведомления о завершении, будильника `ScheduleWakeup` в будущем (таймеры `CronCreate` не держат: `--resume`
  возвращает их сам и после сжатия через `-p`, замеры 27.10; держат только сброс — новая беседа их теряет);
- аргументы запуска восстановимы (`args.go`: имя, `-c`, `--resume`, `--model`, `--effort`, `--agent`, `--add-dir`,
  `--settings`, `--chrome`; любой другой флаг — нельзя).

Перезапуск: SIGTERM (Claude Code выходит мягко, беседа дописана), затем
`claude --dangerously-skip-permissions -n <имя> [флаги] --resume <сессия>` в том же терминале, без реплики (раздел
«Строка роли»).
Любой другой выход claude (`/exit`, Ctrl+C, Ctrl+D, закрытие вкладки, сбой) — выход cl с кодом claude.

Режим — `restart.mode` в конфиге: `log` (по умолчанию) — только журнал «перезапустил бы / не стал бы», `act` —
перезапуск. Конфиг перечитывается на каждой проверке, консоли перезапускать не нужно.

`cl --cl-check` — решение по всем живым интерактивным сессиям сейчас (и запущенным старым cl), печать и строка в
журнал с пометкой `check`; ничего не останавливает.

Решает aguard (`docs/design.md`, «restart»): cl на каждой проверке спрашивает его в сокет
`$XDG_RUNTIME_DIR/aguard/aguard.sock` (`ask.go`, ответ ждёт до 2 с) и перезапускает, только если aguard ответил
`restart` и назвал беседу. Своего решения у cl нет: aguard не ответил — ни перезапуска, ни сжатия, строка в журнал.
Аргументы запуска знает только cl, поэтому почему они не восстановятся (`args_problem`) считает он сам. Строка
журнала пишется один раз на решение (ключ ответа `key`).


## Сжатие в простое

Кэш подсказки живёт час от начала запроса. Беседу с большим контекстом, брошенную дольше часа, следующий запрос
пишет в кэш целиком заново; сжатие до конца часа читает её из живого кэша. Решает aguard (`docs/design.md`,
«compact»): в ответе на тот же вопрос cl поле `compact` — контекст от 100 тыс., 53–57 минут от начала запроса, сессия
свободна, поле ввода пустое по экрану терминала, перезапуск ничего не потеряет. Сжатие — через перезапуск (решение
пользователя 25.10): SIGTERM, `claude <флаги сессии> -p --resume <сессия> /compact` в своём scope без терминала (срок
10 минут), затем подъём `--resume` с теми же флагами, без реплики. Сжатие упало
— беседа поднимается без него, строка в журнал. TERM или HUP во время сжатия — выход cl.

Режим — `restart.compact_mode`: `log` (по умолчанию) — «сжал бы» в журнал один раз на решение, `act` — сжатие,
`off` — молчать. `restart.compact_names` — в `act` сжимать только сессии с этими именами (пилот); пусто — все.
`cl --cl-check` дописывает к строке вердикт сжатия.

## Сброс беседы

Беседу с закрытой работой (контекст и простой — с порогов сжатия, ничего не идёт, таймеров нет, чистое git-дерево)
aguard предлагает сбросить: поле `reset` в ответе (`docs/design.md`, «compact»). Где сброс можно, сжатия нет: в
`compact_against` довод `reset` (пользователь 27.10: «мы должны использовать сброс везде где можем»). Сброс — новая беседа
вместо `/clear`: SIGTERM, затем `claude <флаги сессии> -n <имя>` без `--resume` в том же терминале, первой репликой —
строка роли, только если есть файл возобновления: сброшена закрытая работа без таймеров, напоминать не о чем.
Режим — `restart.reset_mode`: `log` (по умолчанию) — «сбросил бы» в
журнал один раз на решение, `act` — сброс, `off` — молчать; `restart.reset_names` — пилот, как у сжатия.
`cl --cl-check` дописывает к строке вердикт сброса.

## Под своим pty

Сессии с именем из `restart.pty_names` (пусто — ни одной) `cl` запускает под своим pty: ввод человека идёт через `cl`,
вывод claude — в терминал `cl`, терминал на время работы claude сырой и возвращается при любом выходе (Ctrl+D,
`/exit`, закрытая вкладка, паника). Имя проверяется перед каждым подъёмом claude: внесённое в `pty_names` включается
на ближайшем перезапуске, сжатии или сбросе сессии, консоль перезапускать не нужно. Тогда сжатие и сброс можно сделать набором `/compact` и `/clear` в живой сессии —
без перезапуска: фоновые задачи и таймеры `CronCreate` остаются (пилот 26.10), строка роли после `/clear` не нужна
никому, лиду тоже (пользователь 26.10). Режим —
`restart.type_mode`: `log` (по умолчанию) — прежний путь через перезапуск и «под pty набрал бы …» в журнал, `act` —
набор вместо перезапуска, если человек ничего не вводил минуту, `off` — молчать. В `act` cl говорит aguard, что
наберёт (`typed` в вопросе), и процесс claude тот же. Таймеры `CronCreate` сброс не держат: `/clear` их не теряет
(пилот 26.10 18:06 CET). Фоновые команды, мониторы и дети процесса не держат ни сжатие, ни сброс: после `/clear`
команда живёт, и уведомление о её конце приходит в новую беседу (пользователь 26.10 в chooks-master). Работающие
суб-агенты держат только сброс — так решил пользователь. Ввод не терминал (`cl` из скрипта) — claude получает терминал
`cl` напрямую. Экран для проверки поля ввода aguard ищет по терминалу `cl`, не по pty
claude.

Окно доверия к домашней папке («Accessing workspace: ~», «Yes, I trust this folder») под pty `cl` подтверждает сам:
стрелка вниз и Enter (по умолчанию выбрано «No, exit»), строка «подтвердил доверие к …» в журнал. Claude Code не
сохраняет доверие к домашней папке, и без этого каждый подъём claude в `~` стоял бы на окне, пока его не увидит человек
(лид 27.10, 20:48–21:45 CET). Только в домашней папке: к остальным доверие сохраняется после первого «да» человека.
Человек нажимал клавиши после подъёма — окно его. Ответы терминала на запросы claude и фокус клавишами не считаются.

## Строка роли

После перезапуска и сжатия реплики нет, голый `--resume`: беседа поднята целиком, ждавшая ответа сессия ждёт дальше,
а таймеры `CronCreate` `--resume` возвращает сам (замер лида 27.10 09:58 CET на 2.1.311, changelog Claude Code 2.1.110:
«`--resume`/`--continue` now resurrects unexpired scheduled tasks»). Реплика была бы лишним ходом на всём контексте
(пользователь 27.10 09:50 CET: «если консоль работает, не надо её рестартить. А если не работает, то не о чем
напоминать»).

Кто эта сессия, она знает из `prompt` роли: cl отдаёт его флагом `--append-system-prompt` при каждом подъёме (старт,
перезапуск, сжатие, сброс; `{name}` — имя сессии), если в аргументах нет своего флага системного промпта. Claude Code
записывает системный промпт на первом запросе беседы и при `--resume` отдаёт записанный, пока беседу не сожмут
(`--system-prompt-snapshot`, `claude --help`): поэтому флаг — на каждом подъёме, а беседа, начатая без него, получит
роль после ближайшего сжатия.

Файл настроек Claude Code роли — `settings`: варианты `{"dirs": [...], "file": "..."}`, первый, к папкам которого
подходит папка сессии (сама папка или вложенная; без `dirs` — любая). cl отдаёт его флагом `--settings` при каждом
подъёме, как `prompt`: так мастера `~/work` и `~/git` — одна роль с разными файлами (тикет cl-role-settings:
Artifact только у админов, скиллы `~/work` вне `~/work` скрыты). Вариант без `file` — ошибка конфига. Файла нет или в
нём не объект JSON — сессия поднимается без него, ошибка в журнал cl и stderr: без файла роль лишь видит лишний
инструмент или скилл, а отказ в подъёме оставил бы консоль мёртвой до человека. Свой `--settings` в аргументах — файл
роли не добавляется, строка в журнал: Claude Code берёт один `--settings` на запуск, последний вытесняет прежние
(проба 08.11 на 2.1.319: два файла с хуком `SessionStart`, сработал только второй).

После сброса с файлом возобновления и при обычном старте `cl` без своих аргументов (по `on_start` роли) — строка роли: `roles` по имени
сессии, `{why}` — «cl начал новую беседу в 14:05 вместо простаивавшей; Claude Code <версия>» (время местное, без пояса)
или «старт cl на Claude Code <версия>»; путь к свежему файлу возобновления (`~/.claude/restart/<последняя дата>/<имя>.md`,
не старше `resume_max_age_hours`; файл разовый — отдав, cl убирает его в `<дата>/used/` и называет новой сессии этот
путь). Тексты ролей — только в конфиге.

## Новый cl без перезапуска консоли

Живой cl держит бинарник, с которым его запустили. Если cl заменили установкой, `/proc/self/exe` кончается на
« (deleted)». Тогда в точке между двумя запусками claude (перезапуск на новую версию, сжатие, сброс) cl делает exec в
новый бинарник по тому же пути. Состояние передаётся в переменной `CL_UPGRADE` (JSON с полем `v`): имя сессии, номер
запуска и аргументы следующего запуска claude. Новый cl убирает переменную и поднимает claude с этими аргументами. Pid,
терминал и вкладка остаются те же, живую беседу это не трогает. В журнал пишется строка «cl обновлён — перехожу в новый
бинарник». Если exec не вышел, работает прежний cl. Если новый cl не понял состояние, он стартует как обычно.

Сессии из `restart.live_upgrade_names` (пусто — ни одной) cl подхватывает и на ходу, не трогая живой claude: под pty
сжатие и сброс идут набором, и до настоящего перезапуска cl иначе оставался бы старым. На проверке, когда бинарник
заменён, а человек молчит минуту, cl снимает close-on-exec с master pty claude, возвращает терминал в обычный режим и
делает exec. В `CL_UPGRADE` уходят ещё pid claude, номер дескриптора master и время последнего ввода человека. Новый cl
не запускает claude, а ждёт его как своего (claude остаётся дочерним, pid тот же), снова переводит терминал в сырой
режим и шлёт claude SIGWINCH — перерисовать экран. Набранное в поле ввода остаётся. В журнале к строке добавляется «на
ходу, claude pid=N остаётся». Если exec не вышел, всё возвращается как было и в этом запуске claude больше не пробуется.

## Конфиг и журнал

`~/.config/cl/config.json` (образец — `config.json` в репо; `CL_CONFIG` — другой файл, для проверки на тестовой
сессии). Журнал — `restart.journal`, по умолчанию `~/.local/state/cl/restart.log`.

## Scope

Каждый запуск claude идёт в своём scope `agent-<имя>-<pid cl>[-r<n>]` слайса `agents.slice`
(`systemd-run --user --scope`; CPUWeight и IOWeight 40 против 100 у приложений пользователя, лимитов памяти нет).
Без файла слайса или без systemd-run cl отказывается с ошибкой. В новой вкладке Konsole scope живёт около 1–2 с:
Konsole переносит процесс в scope вкладки `tab(<pid оболочки>).scope` (журнал systemd 23.10 17:09: «agent-…scope:
Consumed … over 1.5s wall clock»; 24.10 у всех пяти консолей cgroup — `app-org.kde.konsole-….scope/tab(…).scope`).
В tmux процесс остаётся в `agents.slice`.

## Установка

Вместе с aguard: `graft install` в корне репо ставит закоммиченный `~/bin/cl` атомарной заменой (запущенные
консоли держат старый файл и не задеваются, новые получат новую версию), кладёт `cmd/cl/config.json` в
`~/.config/cl/` (если файла ещё нет) и `cmd/cl/agents.slice` в `~/.config/systemd/user/`.
