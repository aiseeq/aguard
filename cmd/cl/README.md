# cl

Короткий запуск Claude Code: `cl [аргументы claude]` = `claude --dangerously-skip-permissions --allowedTools=Grep,Glob
--add-dir=~/.cache/worktrees --add-dir=~/.cache/claude-tmp -n <имя> [аргументы]`.

`--allowedTools=Grep,Glob` возвращает в Bash настоящие `grep` и `find` вместо встроенных ugrep и bfs (и инструменты Grep и Glob),
остальной набор инструментов не меняется (tools-reference, «Glob tool behavior»; выключателя подмены нет, #69736). Его же
получает `cl -p`, подкоманды — нет. Флаг — обход: ночью его проверяет обход Сна `harness`.

`--add-dir` на `~/.cache/worktrees` (worktree от `graft worktree add`) и `~/.cache/claude-tmp` (`CLAUDE_CODE_TMPDIR`,
scratchpad): без него Claude Code 2.1.310 возвращает cwd Bash в корень сессии после каждого `cd` туда. Несуществующая
папка не передаётся. Его получают первый запуск, перезапуск и `cl -p`. После `cd` в такую папку Primary working
directory сессии меняется так же, как при `cd` в подкаталог корня; каталог проекта (транскрипт, автопамять, скрипты
Workflow) остаётся по папке запуска, `--resume` из неё находит беседу (пробы Сна 25.10).

Имя сессии — по папке запуска: строка таблицы `~/.config/cl/names.tsv` («папка<TAB>имя», `~` раскрывается),
иначе `<папка>-master` для `~/git/<папка>` и `~/work/<папка>`, иначе без имени. Имя занято живой сессией
(реестр `~/.claude/sessions/*.json`) — `-2`, `-3`… Свой `-n`/`--name`, `-p` и подкоманды (`cl mcp list`) — как у claude.

## Перезапуск на новую версию

Интерактивную сессию cl держит дочерним процессом. Раз в `check_seconds` он спрашивает aguard, можно ли перезапустить
её на установленную версию Claude Code (`~/.local/bin/claude` → `~/.local/share/claude/versions/<версия>`), и пишет
смену решения в журнал. Можно — только если всё сразу (`internal/restart/decide.go`; любое непрочитанное — нельзя):

- версия процесса (`/proc/<pid>/exe`) старее установленной;
- Claude Code считает сессию простаивающей (`status: idle` в реестре), а claude-hooks — закончившей ход
  (`$XDG_RUNTIME_DIR/claude-hooks/sessions/<сессия>`: `done` или `waiting`); `paused` — только без фоновых задач
  на последнем Stop (нет файла `<сессия>.tasks`) и когда все таймеры восстановимы ролью;
- транскрипт, состояние и статус не менялись `restart.idle` конфига aguard, ввода в терминал столько же не было (atime pts);
- у процесса нет потомков (фоновые команды Bash, их дети, хуки);
- в транскрипте с начала жизни процесса нет инструмента без результата, фоновой команды, монитора или суб-агента
  без уведомления о завершении, будильника `ScheduleWakeup` в будущем и таймера `CronCreate`, кроме тех, что роль
  ставит заново сама (`restorable_crons` роли в конфиге aguard: лиду — Сон и Дайджест);
- аргументы запуска восстановимы (`args.go`: имя, `-c`, `--resume`, `--model`, `--effort`, `--agent`, `--add-dir`,
  `--settings`, `--chrome`; любой другой флаг — нельзя).

Перезапуск: SIGTERM (Claude Code выходит мягко, беседа дописана), затем
`claude --dangerously-skip-permissions -n <имя> [флаги] --resume <сессия> "<строка роли>"` в том же терминале.
Любой другой выход claude (`/exit`, Ctrl+C, Ctrl+D, закрытие вкладки, сбой) — выход cl с кодом claude.

Режим — `restart.mode` в конфиге: `log` (по умолчанию) — только журнал «перезапустил бы / не стал бы», `act` —
перезапуск. Конфиг перечитывается на каждой проверке, консоли перезапускать не нужно.

`cl --cl-check` — решение по всем живым интерактивным сессиям сейчас (и запущенным старым cl), печать и строка в
журнал с пометкой `check`; ничего не останавливает.

Решает aguard (`docs/design.md`, «restart»): cl на каждой проверке спрашивает его в сокет
`$XDG_RUNTIME_DIR/aguard/aguard.sock` (`ask.go`, ответ ждёт до 2 с) и перезапускает, только если aguard ответил
`restart` и назвал беседу. Своего решения у cl нет: aguard не ответил — ни перезапуска, ни сжатия, строка в журнал.
Аргументы запуска знает только cl, поэтому почему они не восстановятся (`args_problem`) считает он сам. Строка
журнала пишется один раз на решение (ключ ответа `key`).


## Сжатие в простое

Кэш подсказки живёт час от начала запроса. Беседу с большим контекстом, брошенную дольше часа, следующий запрос
пишет в кэш целиком заново; сжатие до конца часа читает её из живого кэша. Решает aguard (`docs/design.md`,
«compact»): в ответе на тот же вопрос cl поле `compact` — контекст от 100 тыс., 53–57 минут от начала запроса, сессия
свободна, поле ввода пустое по экрану терминала, перезапуск ничего не потеряет. Сжатие — через перезапуск (решение
пользователя 25.10): SIGTERM, `claude <флаги сессии> -p --resume <сессия> /compact` в своём scope без терминала (срок
10 минут), затем подъём `--resume` с теми же флагами; строка роли — только если у сессии были таймеры. Сжатие упало
— беседа поднимается без него, строка в журнал. TERM или HUP во время сжатия — выход cl.

Режим — `restart.compact_mode`: `log` (по умолчанию) — «сжал бы» в журнал один раз на решение, `act` — сжатие,
`off` — молчать. `restart.compact_names` — в `act` сжимать только сессии с этими именами (пилот); пусто — все.
`cl --cl-check` дописывает к строке вердикт сжатия.

## Сброс беседы

Беседу с закрытой работой (большой контекст, простой от часа, чистое git-дерево, подсказка Claude Code «/clear to
save» на экране) aguard предлагает сбросить: поле `reset` в ответе (`docs/design.md`, «compact»). Сброс — новая беседа
вместо `/clear`: SIGTERM, затем `claude <флаги сессии> -n <имя>` без `--resume` в том же терминале, первой репликой —
строка роли с файлом возобновления и `reset_note`. Режим — `restart.reset_mode`: `log` (по умолчанию) — «сбросил бы» в
журнал один раз на решение, `act` — сброс, `off` — молчать; `restart.reset_names` — пилот, как у сжатия. Сжатие
важнее сброса. `cl --cl-check` дописывает к строке вердикт сброса.

## Строка роли

Первая реплика после перезапуска, а при обычном старте `cl` без своих аргументов — по `on_start` роли: строка роли
(`roles` по имени сессии, `{why}` — «перезапуск cl на Claude Code <версия>», «сжатие cl…», «сброс cl…» или «старт cl…»), путь к свежему файлу
возобновления (`~/.claude/restart/<последняя дата>/<имя>.md`, не старше `resume_max_age_hours`) и после перезапуска —
`restart_note` (строка служебная, не ответ пользователя), после сброса — `reset_note` (беседа новая). Тексты ролей —
только в конфиге.

## Конфиг и журнал

`~/.config/cl/config.json` (образец — `config.json` в репо; `CL_CONFIG` — другой файл, для проверки на тестовой
сессии). Журнал — `restart.journal`, по умолчанию `~/.local/state/cl/restart.log`.

## Scope

Каждый запуск claude идёт в своём scope `agent-<имя>-<pid cl>[-r<n>]` слайса `agents.slice`
(`systemd-run --user --scope`; CPUWeight и IOWeight 40 против 100 у приложений пользователя, лимитов памяти нет).
Без файла слайса или без systemd-run cl отказывается с ошибкой. В новой вкладке Konsole scope живёт около 1–2 с:
Konsole переносит процесс в scope вкладки `tab(<pid оболочки>).scope` (журнал systemd 23.10 17:09: «agent-…scope:
Consumed … over 1.5s wall clock»; 24.10 у всех пяти консолей cgroup — `app-org.kde.konsole-….scope/tab(…).scope`).
В tmux процесс остаётся в `agents.slice`.

## Установка

Вместе с aguard: `deploy/install.sh` в корне репо собирает `~/bin/cl` через `~/bin/cl.new` и `mv` (запущенные
консоли держат старый файл и не задеваются, новые получат новую версию), кладёт `cmd/cl/config.json` в
`~/.config/cl/` (если файла ещё нет) и `cmd/cl/agents.slice` в `~/.config/systemd/user/`.
