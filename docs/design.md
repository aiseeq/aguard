Источник — разговор пользователя с лидом 24–25.10 (транскрипт лида `~/.claude/projects/-home-alice/0bbcc980-299c-4952-9456-a5d0841affb0.jsonl`) и страница «Набор инструментов для агентов» (https://claude.ai/artifact/HPRg6uPQfYNPK1acqvkkQj, раздел «Страж»). Решения отсюда не пересматривать молча — только обсудив с пользователем.

## Зачем
Пользователь 25.10: «это должен быть один демон который следит за всеми агентами… в виде демона будет удобнее следить за длительными процессами контроля памяти, винта и т.п.»; «это должен быть контроль за всеми ресурсами потребляемыми агентом, за границами его действий. И тут я под контролем имею в виду не только то, чтобы агенты не выжирали весь винт или оперативу, а чтобы страж следил, что этих и других ресурсов в принципе достаточно».

Имя: a = agentic, проект только для агентов, как akit (схема — `~/git/akit/docs/design.md`, «Имена и репозиторий»).

## Три слоя
- **Хуки (claude-hooks)** срабатывают на конкретный шаг агента: перед командой, в конце хода, при отправке реплики. Видят одну сессию в один момент и должны отвечать мгновенно.
- **aguard** — один постоянный демон. Видит все сессии и всю машину сразу, следит за тем, что тянется долго. Сам в ход агента не вмешивается: агенту приходит сообщение.
- **cl** (`~/git/cl`) остаётся тонким запуском: флаги, имя сессии, `agents.slice`, перезапуск в том же терминале. Перезапустить сессию может только её родитель, а родитель — cl. Решение «пора ли перезапускать» (`decide.go`: сессия простаивает, нет фоновых задач и невосстановимых таймеров, версия старее) — это наблюдение за сессией, и оно переезжает в aguard. cl спрашивает aguard «можно?» и сам перезапускает.

## Что входит
| что | сейчас | в aguard |
|---|---|---|
| процессы-сироты умерших сессий | procguard (исходники `~/.local/share/tmpguard`, режим observe) | то же |
| мусор в `/tmp` (это оперативка) и чей он | tmpguard | то же |
| можно ли перезапустить сессию | решение cl | решение здесь, перезапуск — в cl |
| недельные лимиты учёток и переключение | claude-hooks `account rotate`, запускается строкой статуса, то есть только пока она рисуется | постоянное наблюдение и прогноз; строка статуса только показывает |
| «машина занята, подожди» | три копии: graft (`loadgate`, `workers`), `when-idle.sh`, tmpguard | одно правило в библиотеке akit, aguard его применяет |
| снимки «кто съел память» | системный таймер `mem-pressure-snapshot` | то же |
| последняя защита от нехватки памяти | earlyoom | earlyoom остаётся: он должен работать, даже если aguard упал |

Из claude-hooks уходит только переключение учёток с прогнозом (решение лида 25.10). Уведомления, `skill_reload`, `jira_style`, проверка вопросов и строка статуса — реакции на шаг агента, остаются хуками. Правка claude-hooks при переносе — только с «да» пользователя на конкретную правку.

Общую часть с akit (разбор транскриптов, процесс → сессия, давление машины) брать из библиотеки akit, а не копировать: у «процесс → сессия» сейчас пять копий.

## Два вида контроля
1. **Границы одного агента.** Чтобы один агент не отъел память, диск или процессор у всех, и чтобы его действия не выходили за его дерево: чужие проекты, `/tmp`, порты, контейнеры. Нарушение получает сам агент: «твой `route.test` занял 12 ГБ».
2. **Хватает ли ресурса вообще.** Запас и его тренд («диск кончится через 9 дней при нынешнем росте»). Сигнал лиду; пользователю — только когда нужно физическое действие.

Главная мера — **ожидания и отказы**, а не только гигабайты. Больнее всего агенту время простоя: в очереди, без лимита, без входа, без PC. Это механизм для принципа пользователя «Видишь очередь - разберись в причинах» (25.10, `~/.claude/CLAUDE.md`).

## Устройство
- Один конфиг `~/.config/aguard/config.toml` (пример — `deploy/config.example.toml`): общие `lead`, `send_auth`, `[admins]` и разделы наблюдателей `[orphans]`, `[tmp]`, `[memory]`. Неизвестный ключ — ошибка: опечатка не должна молча включать умолчание. `[admins]` в файле заменяет список по умолчанию, а не дополняет. Демон перечитывает конфиг каждый проход; не прочитался — проход пропускается, по неизвестным правилам ничего не делаем.
- Наблюдатели демона — `orphans` (бывший procguard), `tmp` (бывший tmpguard), `memory`; у каждого свой интервал, паника одного не роняет остальных. Состояние — `~/.local/state/aguard/<наблюдатель>/`.
- tmpguard-track остаётся отдельной root-службой (fanotify и proc connector требуют root); aguard читает его снимок из `/run/tmpguard` и `/var/lib/tmpguard`.
- `memory` раз в минуту читает cgroup каждой сессии (`agents.slice/agent-<имя>-<pid cl>.scope`): `memory.peak` с ядра 6.12 сбрасывается записью в свой открытый файл, поэтому каждая запись — пик за прошедший интервал. Память cgroup включает файловый кеш — её же считает `MemoryHigh`, так что порог выбирается по той же мере. Первая запись scope несёт пик за всю жизнь сессии до aguard и в отчёте идёт отдельным столбцом. Записи — дневные JSONL в `~/.local/state/aguard/memory/`, прошлые дни сжимаются, хранятся 60 дней. Отчёт по ролям — `aguard memory report`.
- `restart` — решение «можно ли перезапустить сессию» (бывший `decide.go` cl с его фактами: реестр, claude-hooks, транскрипт, терминал, дети процесса). Интерфейс принял git-admin, владелец cl, 25.10: cl на каждом тике шлёт в сокет `$XDG_RUNTIME_DIR/aguard/aguard.sock` строку JSON `{v, pid, name, args_problem}` и ждёт около 2 с ответ `{v, restart, fresh, against, key, mode, session_id, name, running, installed}`. Нет ответа, другая версия протокола или `error` — cl не перезапускает. Аргументы запуска знает только cl, поэтому `args_problem` считает он сам; его флаги сессии (обход cc-cwd-reset) тоже остаются в cl. Переход: сначала cl спрашивает aguard параллельно со своим решением и пишет расхождения, затем отдельным коммитом переключается на ответ aguard и удаляет свою копию. Перед этим git-admin получает сверку журналов: сколько тиков и сколько расхождений. Ручной вопрос — `aguard restart ask -pid N`; `-claude` подставляет другую ссылку на установленный claude, чтобы проверить решение «как при новой версии».
- Новый раздел конфига — сначала новый бинарь, потом раздел в живом конфиге: старый демон считает его неизвестным ключом и пропускает проходы (25.10 так пропущен один проход).

1. procguard и tmpguard под одной крышей, один конфиг.
2. Решение о перезапуске из cl (cl спрашивает aguard).
3. Наблюдение за ожиданиями и отказами из таблицы выше, сводка лиду. Дешёвый признак, что машина душит агентов, — отмены хуков по таймауту (`hook_cancelled` с `timedOut` в транскриптах).
